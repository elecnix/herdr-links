## Herdr navigation references

When `HERDR_ENV=1`, make reported live agent, workspace, tab, and shell-pane references clickable. Obtain current IDs from the invoking Herdr session, then run `node "@PLUGIN_ROOT@/dist/cli.js" link <agent|workspace|tab|pane> <ID> --label "<ID> — <short description>" --scheme https` and copy its Markdown output verbatim (not in code formatting). Prefer `--scheme https` here. The reserved `https://herdr.invalid` host is unroutable, so a click that misses the plugin opens a browser error page instead of leaking the request to a real site, which is the safe failure mode for a link an agent prints. Generation is read-only; do not focus a target just to report it. Use pane IDs for agents, never `terminal_id`; use `pane` for ordinary shell splits. Agent references validate detected-agent membership and then use exact pane focus so the visible Herdr 0.9 surface follows. Never invent URLs, reuse an old link after a socket/session restart, or select another socket to make an ID resolve. If verification fails, report plain text with the limitation.

Tell the user **Control + left-click**, including on macOS. If the links render as plain text rather than clickable, the harness is not emitting hyperlinks: it only does so for terminals it recognizes, and Herdr clears `TERM_PROGRAM` in pane shells, so set `FORCE_HYPERLINK=1` in the harness environment. If a browser opens or navigation fails, do not reuse the link: verify Herdr mouse capture is enabled, regenerate it for the current socket/version, and inspect `herdr plugin log list --plugin herdr-links --limit 5`. Terminal-native link gestures bypass Herdr navigation, and a fullscreen agent UI may consume the click entirely. Links are only for navigation within the generating Herdr session, not cleanup permission. Tab/workspace links select that location's existing pane; only agent/pane links select an exact split. Outside Herdr, use plain IDs. No global rules or terminal settings should be changed for this convention.

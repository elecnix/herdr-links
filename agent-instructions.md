## Herdr navigation references

When `HERDR_ENV=1`, make reported live agent, workspace, tab, and shell-pane references clickable. Write the Markdown link yourself rather than calling a tool for it. The link is the reserved `https://herdr.invalid/v1/<agent|workspace|tab|pane>/<ID>` plus a label:

    [<short description>](https://herdr.invalid/v1/tab/w19:tF)

Use the live ID from the invoking Herdr session. A link may also carry a session fingerprint between the version and the kind, as `https://herdr.invalid/v1/<sha256>/tab/w19:tF`. That form binds the link to the socket which minted it. Either way the link resolves for as long as its target lives. Print the link verbatim as Markdown, not inside code formatting. Writing a link is read-only. Do not focus a target just to report it. Use pane IDs for agents, never `terminal_id`. Use `pane` for ordinary shell splits. Never invent an ID. A tab or pane herdr has closed never reappears, so a stale link fails rather than focusing the wrong place, but confirm a target is live before you report it. If verification fails, report plain text with the limitation.

Tell the user **Control + left-click**, including on macOS. Command-click belongs to the outer terminal and opens a browser instead. If the links render as plain text rather than clickable, the harness is not emitting hyperlinks at all: it emits them only for terminals it recognizes, and Herdr clears `TERM_PROGRAM` in pane shells, so set `FORCE_HYPERLINK=1` in the harness environment. If a browser opens or navigation fails, do not reuse the link: verify Herdr mouse capture is enabled, regenerate it for the current socket/version, and inspect `herdr plugin log list --plugin herdr-links --limit 5`. A click that never reaches the plugin leaves no log entry, so an empty log means the click did not arrive rather than that the handler failed. Links only navigate within the generating Herdr session. Tab/workspace links select that location's existing pane; only agent/pane links select an exact split. Outside Herdr, use plain IDs. No global rules or terminal settings should be changed for this convention.

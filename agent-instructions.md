## Herdr navigation references

When `HERDR_ENV=1`, make reported live agent, workspace, tab, and shell-pane references clickable. Obtain current IDs from the invoking Herdr session, then run `node "@PLUGIN_ROOT@/dist/cli.js" link <agent|workspace|tab|pane> <ID> --label "<ID> — <short description>" --scheme https` and copy its Markdown output verbatim (not in code formatting). The `--scheme https` flag matters in this harness: Claude Code turns only `http` and `https` Markdown links into real OSC 8 hyperlinks, and renders a custom `herdr://` target as plain text with no click target. Generation is read-only; do not focus a target just to report it. Use pane IDs for agents, never `terminal_id`; use `pane` for ordinary shell splits. Agent references validate detected-agent membership and then use exact pane focus so the visible Herdr 0.9 surface follows. Never invent URLs, reuse an old link after a socket/session restart, or select another socket to make an ID resolve. If verification fails, report plain text with the limitation.

Tell the user **Control + left-click**, including on macOS. The https form is a reserved host that Herdr routes to this plugin, so it opens a tab instead of a browser; it exists precisely because an agent harness may refuse to hyperlink a private scheme. If a browser opens or navigation fails, do not reuse the link: verify Herdr mouse capture is enabled, regenerate it for the current socket/version, and inspect `herdr plugin log list --plugin herdr-links --limit 5`. Terminal-native link gestures bypass Herdr navigation, and a fullscreen agent UI may consume the click entirely. Links are only for navigation within the generating Herdr session, not cleanup permission. Tab/workspace links select that location's existing pane; only agent/pane links select an exact split. Outside Herdr, use plain IDs. No global rules or terminal settings should be changed for this convention.
